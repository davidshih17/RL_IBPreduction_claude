# SAILIR

**S**elf-supervised **AI** for **L**oop **I**ntegral **R**eduction.

Code, trained model, and benchmark data accompanying the paper:

> **Learning to Unscramble Feynman Loop Integrals with SAILIR**
> David Shih, 2026.

SAILIR is a transformer-based classifier that guides Integration-by-Parts (IBP)
reduction of Feynman integrals one step at a time. Training is fully
self-supervised: random reduction trajectories are generated by scrambling
known master integrals with random IBP identities, and the classifier learns
to undo the scrambles in weight-decreasing order. At inference time, a
hierarchical orchestrator submits independent one-episode beam-search workers
to a Condor cluster, with each worker reducing a single integral by one weight
level. Per-worker memory stays approximately flat as integrals get more
complex, in contrast to Laporta-based reducers whose memory grows rapidly with
complexity.

## Requirements

- Python 3.10+
- PyTorch (CPU is fine for inference; CUDA recommended for training)
- NumPy, Matplotlib

```bash
pip install torch numpy matplotlib
```

For the Kira side of the benchmark you additionally need
[Kira](https://gitlab.com/kira-pyred/kira) and a Fermat binary on your `$PATH`
(used only for reproducing the comparison; not required for SAILIR itself).

The async orchestrator in `scripts/eval/hierarchical_reduction.py` assumes an
[HTCondor](https://htcondor.org/) cluster. A single-integral one-episode
reduction (`scripts/eval/onestep_worker.py`) runs on any machine.

## Quick start: reduce an integral with the published model

```bash
python scripts/eval/onestep_worker.py \
    --integral 2,1,2,1,2,2,-4 \
    --model-checkpoint checkpoints/best_model.pt \
    --output reduction.pkl \
    --beam_width 20 \
    --prime 1009 \
    --paper-masters-only \
    -v
```

This reduces `I[2,1,2,1,2,2,-4]` (the simplest integral in the paper's
benchmark) by one weight level, dumping the reduction path to `reduction.pkl`.
Adjust `--integral` for any other index tuple.

To verify the resulting reduction satisfies the IBP equations:

```bash
python scripts/eval/replay_reduction_path.py --path reduction.pkl
```

## End-to-end reproduction

### 1. Generate self-supervised training data

Scramble + unscramble corner integrals across all 63 sectors:

```bash
python scripts/data_gen/generate_multisector_data.py \
    --n_scrambles 80000 \
    --min_steps 5 --max_steps 20 \
    --output data/raw_jsonl/scrambles_seed0.jsonl \
    --start_seed 0 \
    --prime 1009 \
    --ibp_path scripts/data_gen/IBP \
    --li_path  scripts/data_gen/LI
```

For the paper we ran ~80k scrambles, yielding ~1.06M training samples (see
§IV.B). Each sample is one step of an unscrambling trajectory. Parallelise
by launching multiple jobs with different `--start_seed` and `--output`
filenames; they can be merged in the next step.

### 2. Pack JSONL into PyTorch tensors

```bash
python scripts/data_gen/preprocess_to_tensors.py \
    --input  data/raw_jsonl/ \
    --output data/multisector/ \
    --val-fraction 0.1 \
    --seed 0
```

Reads every `*.jsonl(.gz)` under `--input`, shuffles, splits into train/val,
and writes `train.pt` + `val.pt` containing packed expression / substitution
/ action tensors with offsets.

### 3. Train the classifier

```bash
python scripts/train/train_classifier.py \
    --data_dir   data/multisector/ \
    --output_dir checkpoints/ \
    --epochs 30 \
    --batch_size 256 \
    --lr 4e-4 \
    --prime 1009 \
    --device cuda
```

Reproduces the published checkpoint to within initialisation noise. On the
paper's hardware (single GPU) one epoch takes ~5 minutes; total run ~3 hours.
Best validation accuracy at epoch 22 (90.8% top-1). Use the training log
output to regenerate Fig. 2:

```bash
python scripts/plots/plot_training_curve.py \
    --log results/training_log/train.log
```

### 4. Reduce the 16 benchmark integrals

For each of the 16 integrals in Table 1 of the paper, run the async
orchestrator. It submits one Condor worker per non-master integral
encountered, caches results, and writes a single pickle when done.

```bash
INTEGRALS=( "2,1,2,1,2,2,-4"  "1,1,2,2,1,3,-5"  "1,1,3,2,2,1,-6"  "2,3,1,1,2,1,-7"
            "2,2,2,1,1,3,-4"  "1,1,2,3,2,2,-5"  "1,4,2,1,2,1,-6"  "2,1,1,2,3,2,-7"
            "2,3,1,3,1,2,-4"  "1,2,2,2,1,4,-5"  "3,2,3,2,1,1,-6"  "3,1,1,1,1,5,-7"
            "2,3,3,3,1,1,-4"  "2,2,3,3,2,1,-5"  "3,2,1,3,2,2,-6"  "2,2,3,3,1,2,-7" )

mkdir -p logs results work-dir

for I in "${INTEGRALS[@]}"; do
    label=$(echo "$I" | tr ',' '_' | tr '-' 'm')
    python -u scripts/eval/hierarchical_reduction.py \
        --integral $I \
        --output   results/reduction_${label}.pkl \
        --work-dir work-dir/${label} \
        --model-checkpoint checkpoints/best_model.pt \
        --beam_width 20 \
        --prime 1009 \
        --paper-masters-only \
        --beam-sort mixed \
        > logs/async_${label}.log 2>&1 &
done
wait
```

The orchestrator uses the system Python (`sys.executable`) for spawned
workers; set `SAILIR_PYTHON=/path/to/python` if your Condor environment needs
a specific interpreter.

### 5. Collect benchmark results and reproduce the plots

```bash
python scripts/eval/collect_benchmark_results.py \
    --logdir     logs/ \
    --resultdir  results/ \
    --scratchdir work-dir/

python scripts/plots/plot_benchmark_comparison.py \
    --sailir-csv results/benchmark_mixed_summary_v13.csv \
    --kira-csv   results/kira_benchmark.csv \
    --out        results/benchmark_comparison.pdf
```

The published `results/sailir_benchmark.csv` is the exact CSV used to produce
Fig. 3 in the paper; passing `--sailir-csv results/sailir_benchmark.csv`
regenerates the published figure verbatim.

### 6. Reproduce the Kira side of the comparison (optional)

```bash
export KIRA=/path/to/kira/bin/kira
export FERMATPATH=/path/to/fermat/fer64
cd scripts/kira/
./run_benchmark_s7.sh           # the most memory-intensive integrals
```

This will produce one `kira_bench_*.log` per integral. The published
`results/kira_benchmark.csv` summarises these.

## Model architecture

`sailir/classifier.py` defines a single class, `IBPActionClassifier` (alias
`IBPActionClassifierV5` for backward compatibility with the published
checkpoint), consisting of:

| Component                           | Role                                                  |
|-------------------------------------|-------------------------------------------------------|
| `IntegralEncoder`                   | 7-tuple index + (r, s) weight features → 256-d vector |
| `CoefficientEncoder`                | Finite-field coefficient → 256-d vector               |
| `ActionEncoder`                     | (template index, seed delta) → 256-d vector           |
| `TransformerExpressionEncoderWithTarget` | Self-attention over [CLS] [TARGET] term_1 ... term_N |
| `FullSubstitutionEncoder`           | Per-substitution embed → Transformer pool             |
| `SectorEncoder`                     | 6-bit mask → 256-d vector                             |
| `CrossAttentionScorer`              | Multi-layer cross-attention scoring actions vs expression terms |

Defaults: `embed_dim=256`, 4 attention heads, 2 layers for each of the three
encoders, 2 layers of cross-attention scoring. Total: **7.7M parameters**.
